## OpenEPaperLink Home Assistant integration

- Project: [OpenEPaperLink/Home_Assistant_Integration](https://github.com/OpenEPaperLink/Home_Assistant_Integration),
  version 3.0.0 (commit `f28c217`), the Home Assistant integration of the
  OpenEPaperLink project (code owners: jonasniesner, g4bri3lDev).
- What is ported (rewritten in JavaScript in `src/constants.js`, `src/ap/`
  and `src/model.js`): the HTTP paths of the access point (`/get_db` paged by
  `pos`, `/tagtypes/<type>.json`, `/imgupload` as multipart with `mac` and
  `dither`, a JPEG for the image), the websocket address (`/ws`) and its
  messages (`sys`, `tags`, `errMsg` "REBOOTING"), the fields read from them
  (`batteryMv`, `temperature`, `lastseen`, `nextcheckin`, `hwType`, `alias`,
  `isexternal`, `apstate`, `lowbattcount`, `timeoutcount`), the names of the
  access point states, the battery estimate from the voltage
  (`_calculate_battery_percentage`), no battery for a tag served by another
  access point, and the idea of one upload at a time with a pause between
  uploads (`UploadQueueHandler`). No Python runs here, no font or image of
  the project is used: the 5x9 font and the JPEG encoder are written for this
  integration.
- Licence: Apache License 2.0. Its `LICENSE` file names no copyright holder
  and the project has no `NOTICE` file; the licence is reproduced below as
  its `LICENSE` file reads.

## OpenEPaperLink access point firmware (read only, nothing copied)

The HTTP and websocket behaviour of the access point (the multipart field
order of `/imgupload`, its 409 "busy" answer with Retry-After, its 1 MB upload
limit, the `continu` paging of `/get_db`) was checked by reading the source
of the firmware ([OpenEPaperLink/OpenEPaperLink](https://github.com/OpenEPaperLink/OpenEPaperLink),
`ESP32_AP-Flasher/src/web.cpp` and `tag_db.cpp`). That repository is under
CC BY-NC-SA 4.0: none of its code, text or resources is copied or shipped
here; only interoperability facts (paths, field names, statuses) are used.
